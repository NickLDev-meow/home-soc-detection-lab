# T1059.001 — Encoded / Obfuscated PowerShell Execution

| | |
|---|---|
| **Tactic** | Execution |
| **Technique** | [T1059.001 — Command and Scripting Interpreter: PowerShell](https://attack.mitre.org/techniques/T1059/001/) |
| **Severity** | Medium → High (context-dependent) |
| **Data source** | Sysmon Event ID 1 (Process Creation); enrich with Event ID 4104 (PowerShell Script Block Logging) |
| **Status** |  written · ✅ verified in lab (rule `100201`, Wazuh) — see [incident-001](../investigations/incident-001-encoded-powershell.md) |

## Why this matters

`powershell.exe -EncodedCommand <base64>` is one of the most common ways attackers run a payload without dropping a script to disk. The base64 blob hides the real command from casual log review, and it shows up constantly in commodity malware, Cobalt Strike, and living-off-the-land tradecraft. A SOC that can't see through `-enc` is blind to a huge slice of real intrusions — so this is a foundational detection.

The trick for an analyst: **detecting the *pattern* (encoded execution) is easy; the value is decoding the blob and judging intent.** This detection fires on the pattern, and the investigation decodes it.

## What "normal" looks like vs. the attack

- **Benign:** some legitimate installers and management tools use `-EncodedCommand`. That's why this is a *lead*, not an auto-block — tuning notes below.
- **Malicious:** short-lived `powershell.exe` with `-enc` / `-e` / `-encodedcommand`, often spawned by a non-shell parent (Office app, `wscript`, `mshta`, a scheduled task), frequently combined with `-nop -w hidden - exec bypass`.

## Detection logic (Sigma — portable source of truth)

```yaml
title: Encoded PowerShell Command Execution
id: 9a3c1f6e-1b2d-4c7a-9f10-bastion0001
status: experimental
description: Detects PowerShell launched with an encoded command, a common defense-evasion / obfuscation technique.
references:
  - https://attack.mitre.org/techniques/T1059/001/
author: Bastion SOC Lab
logsource:
  category: process_creation
  product: windows
detection:
  selection_img:
    Image|endswith:
      - '\powershell.exe'
      - '\pwsh.exe'
  selection_flags:
    CommandLine|contains:
      - ' -enc '
      - ' -e '
      - '-EncodedCommand'
      - ' -ec '
  condition: selection_img and selection_flags
falsepositives:
  - Some legitimate software management / deployment tools use -EncodedCommand
level: high
tags:
  - attack.execution
  - attack.t1059.001
```

## Sentinel analytics rule (KQL — paste-ready)

```kql
// T1059.001 Encoded PowerShell — Microsoft Sentinel scheduled analytics rule
// Data: Sysmon EID 1 via AMA (Event table) — adjust table name if using
// the Sysmon DCR that lands in a custom table.
Event
| where Source == "Microsoft-Windows-Sysmon" and EventID == 1
| extend ed = parse_xml(EventData)
| extend Image       = tostring(ed.DataItem.EventData.Data[4].["#text"])
| extend CommandLine = tostring(ed.DataItem.EventData.Data[10].["#text"])
| extend ParentImage = tostring(ed.DataItem.EventData.Data[20].["#text"])
| where Image has_any ("powershell.exe", "pwsh.exe")
| where CommandLine has_any (" -enc ", " -e ", "-EncodedCommand", " -ec ")
| extend SuspiciousParent = ParentImage has_any
    ("winword.exe","excel.exe","outlook.exe","mshta.exe","wscript.exe","cscript.exe")
| project TimeGenerated, Computer, ParentImage, Image, CommandLine, SuspiciousParent
| order by TimeGenerated desc
```

> **MITRE tagging in the rule:** set Tactics = `Execution`, Techniques = `T1059.001` in the Sentinel rule wizard so the incident inherits ATT&CK context automatically.

### Optional enrichment — decode the blob in KQL

```kql
// Surfaces the decoded command directly in the alert when the base64 is captured
| extend b64 = extract(@"(?i)-e(?:nc|ncodedcommand)?\s+([A-Za-z0-9+/=]{20,})", 1, CommandLine)
| extend Decoded = replace_string(tostring(base64_decode_toarray(b64)), " ", "")
```

## Wazuh rule

```xml
<!-- local_rules.xml — fires on Sysmon EID 1 with encoded PowerShell -->
<group name="sysmon,attack,t1059_001,">
  <rule id="100201" level="12">
    <if_group>sysmon_event1</if_group>
    <field name="sysmon.image">(?i)\\\\(powershell|pwsh)\.exe$</field>
    <field name="sysmon.commandLine">(?i)\s-e(nc|ncodedcommand|c)?\s</field>
    <description>Encoded PowerShell execution (T1059.001) on $(win.system.computer)</description>
    <mitre>
      <id>T1059.001</id>
    </mitre>
  </rule>
</group>
```

## False positives & tuning

| Source of noise | How to tune |
|---|---|
| SCCM / Intune / RMM tools using `-EncodedCommand` | Allowlist by `ParentImage` (the management agent) or by signed publisher, not by suppressing the whole rule |
| Admin automation scripts | Allowlist specific decoded command hashes, or specific service accounts on specific hosts |
| Legit short `-e` flags in unrelated tools | Anchor the regex to `powershell`/`pwsh` image only (done above) |

**Raise severity** when `SuspiciousParent == true`, when paired with `-nop`/`-w hidden`/`bypass`, or when the decoded blob contains `IEX`, `DownloadString`, `FromBase64String`, or a URL.
